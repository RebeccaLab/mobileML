# Mobile deepfake detection

This repository supports the study question:

> Can deepfake detection models perform well when compressed enough to run on
> mobile hardware?

The study compares detection accuracy before and after model compression. The
benchmark data must already be labeled as real or manipulated so that the
experimental results are comparable.

## Dataset policy

The raw video and frame datasets are too large for this GitHub repository and
remain on the lab workstation (`linlab2`). This repository stores the dataset
inventory, label conventions, provenance, and evaluation protocol instead of
the raw files.

- Dataset details: [`docs/datasets.md`](docs/datasets.md)

The current benchmark collection contains:

- **FaceForensics++ (FF++)** for training and in-domain evaluation.
- **Celeb-DF++** for external generalization evaluation across 22 newer fake
  generation methods.
- **DF40** for evaluation across 40 manipulation techniques, including
  methods and source domains not represented in the FF++/Celeb-DF training
  data.

The raw data is intentionally excluded by `.gitignore`. The verified lab
paths and required label mappings are documented in the dataset inventory
below.

## Planned comparison

The intended comparison is to evaluate the same detector before and after
compression on the same labeled splits, then compare its accuracy on both the
in-domain FF++ test set and the external Celeb-DF++ and DF40 test sets. Model
size, memory use, and mobile latency should also be recorded where available
so that accuracy can be interpreted alongside deployment cost.

### FaceForensics++ (FF++)

FF++ contains original source videos and manipulated versions generated by
multiple face-manipulation methods. The prepared copy contains:

- `Original` — real, label `0`.
- `Deepfakes`, `Face2Face`, `FaceSwap`, `NeuralTextures`, and `FaceShifter` —
  fake, label `1`.

It uses the standard video-level split of 720 training, 140 validation, and
140 test videos. The prepared face-frame inventory is:

| Split | Real frames | Fake frames | Total |
| --- | ---: | ---: | ---: |
| Training | 21,600 | 21,600 | 43,200 |
| Validation | 4,200 | 4,200 | 8,400 |
| Test | 4,200 | 4,200 | 8,400 |

Local path: `/home/pcl/Deepfake-Detection/prepared_dataset`.

FF++ is the primary training dataset and the in-domain baseline test set.
Official project: <https://github.com/ondyari/faceforensics>.

### Celeb-DF++

Celeb-DF++ is a newer external generalization benchmark, not the older
Celeb-DF v2 dataset. The lab copy extracts its test videos under the root
directory `Celeb-DF-v3`. It contains 22 fake methods in three scenarios:

- 8 face-swap methods.
- 7 face-reenactment methods.
- 7 talking-face methods.

The prepared test manifest contains 5,418 videos: 178 real and 5,240 fake.
The archive is `Celeb-DF++.zip` and the local paths are:

```text
/home/pcl/Deepfake-Detection/external_data/celeb_df_pp/test_videos
/home/pcl/Deepfake-Detection/external_data/celeb_df_pp/test_videos/test_manifest.jsonl
```

The nested `FaceSwap/Celeb-DF-v2` directory is only one source/method subset
inside the larger Celeb-DF++ benchmark; it does not change the identity of
the overall dataset to Celeb-DF v2. Celeb-DF++ is used as an external test
set. Paper: <https://arxiv.org/abs/2507.18015>.

### DF40

DF40 contains 40 distinct deepfake generation techniques:

- 10 face-swapping methods.
- 13 face-reenactment methods.
- 12 entire-face-synthesis methods.
- 5 face-editing methods.

Thirty-one methods use FF++ or Celeb-DF source domains, identified by `ff` or
`cdf` in the official manifests. The remaining nine test-only methods use
different source domains: DeepFaceLab (UADFV), HeyGen (FFHQ), MidJourney-6
(FFHQ), WhichIsReal (FFHQ), CollabDiff (CelebA), e4e (CelebA), StarGAN
(CelebA), StarGANv2 (CelebA), and StyleCLIP (CelebA). “Unknown” means the
source domain/generation setting is unseen relative to the FF++/Celeb-DF
training domain; it does not mean missing labels.

Local paths:

```text

/home/pcl/Deepfake-Detection/preprocessing/dataset_json
```

Official project: <https://github.com/YZY-stack/DF40>.

### Evaluation protocol

1. Train the uncompressed baseline on the FF++ training split.
2. Select settings using the FF++ validation split.
3. Compare uncompressed and compressed models on the held-out FF++ test
   split.
4. Evaluate both models without fine-tuning on Celeb-DF++ and DF40.
5. Report accuracy with the class counts and label mapping used for each
   dataset, retaining per-method and per-source-domain results for DF40.

The external test sets should not be used for training or compression tuning.
Because they are not class-balanced, accuracy should be accompanied by
per-class results or balanced accuracy where possible.
